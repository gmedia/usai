# Wasmtime 50: the vendor goes, the behaviour stays

**2026-10-24.** Wasmtime 50.0.0 (2026-10-20) carries both patches this
repository vendored on 48.0.2: the pagemap slot reset (#14357) and
`Engine::release_idle_pool_memory` (#14419). `vendor/` is deleted and the
workspace depends on `wasmtime = "50"` and `wasmtime-wizer = "50"` from
crates.io. The upgrade needed no source change beyond the image
fingerprint's version string.

## How the release was checked

By the file, not the date (`vendor/README.md` had the rule, because v49.0.1
shipped after the merge without the change): the production half of
`crates/wasmtime/src/runtime/vm/sys/unix/pagemap.rs` at tag `v50.0.0` is
identical to the vendored copy, and `Engine::release_idle_pool_memory` is a
public method in `crates/wasmtime/src/engine.rs` at the same tag.

## Behaviour

`engine::wasm::tests` on the released crate, all green:
`a_reused_slot_is_fresh_even_after_its_pages_were_paged_out` (run on a host
with swap, so it exercises the paged-out case and not only the ordinary
reset), `a_reused_slot_is_fresh_after_fragmented_writes`,
`a_reused_slot_is_fresh_without_the_pagemap_scan`,
`the_idle_release_respects_its_floor_and_leaves_the_slot_usable`, and the new
`wasmtime_version_matches_the_lockfile`.

## Cost

`tests/profile_bundles.rs` `interpreter_vs_memory`, the 48.0.2-vendored build
(a worktree at the previous commit) and the 50.0.0 build run **alternately,
20 pairs, pinned to one core** of the developer laptop (WSL2, 16 vCPU, busy:
load 3–6 from other work, so single runs are not comparable — an earlier
before/after pair taken an hour apart showed QuickJS, which does not use
Wasmtime, 23 % slower).

| | 48.0.2 + patches | 50.0.0 |
|---|---|---|
| hello, per request (median) | 0.298 ms | 0.299 ms |
| CPU-bound guest loop (median) | 254.4 ms | 254.3 ms |
| minor faults per request | 0 | 0 |

50.0.0 was the slower of the pair in 13 of 20 loop runs and 9 of 20 hello
runs — what chance gives. No difference is measurable here. The research VM
used for earlier campaigns has been repurposed, so this was not repeated on a
quiet host.
